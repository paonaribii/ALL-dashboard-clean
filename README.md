# UFUND Executive Dashboard: หน้าสรุปภาพรวมสำหรับผู้บริหาร

> **สรุปสั้นๆ:** เว็บที่รวมตัวเลขสำคัญของธุรกิจขายมือถือแบบผ่อนไว้ในหน้าเดียว
> ผู้บริหารเปิดดูได้เลยว่ามีสัญญาผ่อนกี่สัญญา ลูกค้าค้างจ่ายเท่าไร และเครื่องลงทะเบียนครบหรือยัง
> แล้วกรองดูตามยี่ห้อ สาขา ภาค หรือช่วงวันที่ได้

## ที่มา

เวอร์ชันแรกทำด้วย Google Apps Script (สคริปต์ที่รันบน Google Sheets) ซึ่งดึงข้อมูลจากชีทสดๆ
ทุกครั้งที่มีคนเปิด พอข้อมูลมากขึ้น หน้าเว็บก็โหลดช้าและแก้ไขหน้าตาได้ยาก
จึงย้ายมาทำเป็นเว็บแยก โดย **คำนวณสรุปไว้ล่วงหน้า** ให้หน้าเว็บแค่โหลดผลไปแสดง

## ในหน้า dashboard มีอะไรบ้าง

- **ภาพรวมสัญญา:** จำนวนสัญญาและยอดผ่อนรวม พร้อมกราฟแนวโน้มรายวัน/รายเดือน
- **ลูกค้าค้างจ่าย:** แบ่งกลุ่มตามจำนวนงวดที่ค้าง (ค้าง 1 งวด, 2 งวด, ...)
- **สถานะการลงทะเบียนเครื่อง (MDM):** เครื่องไหนลงทะเบียนสำเร็จ ไม่สำเร็จ หรือยังไม่พบข้อมูล
  (MDM คือระบบที่ใช้ล็อกเครื่องได้ถ้าลูกค้าไม่ผ่อนต่อ)
- **สรุปตามสาขาและผู้ดูแลพื้นที่:** เปรียบเทียบผลงานแต่ละสาขา และผู้จัดการแต่ละเขต
- **ตัวกรองชุดเดียวใช้ได้ทุกหน้า:** เลือกยี่ห้อ ภาค หรือช่วงวันที่ครั้งเดียว แล้วทุกกราฟเปลี่ยนตาม
  คลิกที่ตัวเลขเพื่อเจาะดูรายละเอียดได้

## ทำงานอย่างไร

```
ข้อมูลสัญญา (ฐานข้อมูล SQLite) ─┐
ไฟล์สถานะเครื่อง MDM (Excel) ────┤──► สคริปต์ build คำนวณสรุปล่วงหน้า ──► ไฟล์ข้อมูลบีบอัด
ข้อมูลบิลค้าง (Google Sheets) ───┘                                         │
                                                                         ▼
                                                     หน้าเว็บ (ต้องใส่รหัสผ่านก่อนเข้า)
```

## ความท้าทาย และวิธีแก้

**1. ข้อมูลเยอะ แต่หน้าเว็บต้องเร็ว**
ฐานข้อมูลสัญญามีขนาดประมาณ 350 MB ถ้าค้นทุกครั้งที่มีคนเปิดหน้าเว็บจะช้ามาก
จึงคำนวณสรุปไว้ก่อนแล้วบีบอัดเป็นไฟล์เดียว หน้าเว็บโหลดแค่ไฟล์นั้น

**2. วัดก่อนตัดสินใจ**
ตอนจะเพิ่มให้ดูข้อมูลละเอียดถึงรายวัน กังวลว่าข้อมูลจะใหญ่จนเว็บช้า
เลยวัดดูจริงก่อน พบว่าข้อมูลเพิ่มขึ้นแค่ประมาณ 7.7% (จาก ~537,000 เป็น ~579,000 แถว)
และความเร็วตอนสลับหน้าแทบไม่เปลี่ยน จึงเปิดใช้ได้เลยโดยไม่ต้องตัดข้อมูลทิ้ง

**3. ข้อมูลสถานะเครื่องมาจากหลายไฟล์**
ไฟล์สถานะ MDM ถูกส่งมาหลายรอบ แต่ละรอบอาจมีเครื่องซ้ำกัน โปรแกรมจะเก็บทุกรอบไว้
และใช้ข้อมูลจากไฟล์ล่าสุดก่อน จับคู่กับสัญญาด้วยเลขเครื่อง (IMEI หรือ Serial ของ Apple)

**4. ข้อมูลลูกค้าต้องปลอดภัย (PDPA)**
- ข้อมูลจริง ไฟล์ Excel และรหัสผ่านทั้งหมดไม่ถูกอัปขึ้น git
- ทุกหน้าต้องใส่รหัสผ่านก่อน และการ login ทำตามแนวทางความปลอดภัยมาตรฐาน
  (คุกกี้ที่ปลอมไม่ได้และหมดอายุเอง, ป้องกันการฝังหน้าเว็บในเว็บอื่น ฯลฯ)

## สำหรับนักพัฒนา

**เทคโนโลยีที่ใช้:** Node.js 22 · SQLite (better-sqlite3) · JavaScript/CSS ล้วน (ไม่ใช้ framework) ·
Python (นำเข้า Excel) · Vercel หรือ Cloudflare Pages + KV · node:test

รายละเอียดระบบ login: คุกกี้ session เซ็นด้วย HMAC-SHA256 (HttpOnly, Secure, SameSite=Strict, อายุ 8 ชั่วโมง),
เทียบรหัสผ่านแบบ constant-time และตั้ง security header (CSP, X-Frame-Options, Referrer-Policy)

### วิธีรัน

```bash
npm install
cp .env.example .env        # ตั้ง DASHBOARD_PASSWORD (8+ ตัว), SESSION_SECRET (32+ ตัว), Sheet ID
# วางไฟล์ data/contracts.db (ไม่อยู่ใน git เพราะเป็นข้อมูลจริง)
npm run build:data          # คำนวณข้อมูลและสร้างหน้าเว็บ
npm start                   # เปิดที่ http://127.0.0.1:4191
```

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run build` | ดึงข้อมูลล่าสุดจาก Google Sheets แล้วสร้างหน้าเว็บใหม่ |
| `npm run build:data` | คำนวณข้อมูลใหม่จาก `contracts.db` แล้วสร้างหน้าเว็บ |
| `python scripts/import-mdm.py "<ไฟล์ MDM>.xlsx"` | นำเข้าสถานะเครื่อง MDM แล้วจับคู่กับสัญญาใหม่ |
| `npm test` | ทดสอบว่าตัวเลขและตัวกรองถูกต้อง |
| `npm run deploy:cloudflare` | อัปขึ้น Cloudflare Pages (คำสั่งเดียวจบ) |

### โครงสร้างโปรเจกต์

```
client/        JavaScript/CSS ของหน้าเว็บ (ถูกรวมเข้า public/index.html ตอน build)
source/        หน้าเว็บต้นฉบับจากเวอร์ชัน Apps Script (ใช้เป็นแม่แบบ)
scripts/       คำนวณข้อมูล, ดึง Google Sheets, นำเข้า MDM, deploy
api/ lib/      ระบบ login และส่งข้อมูล (รันในเครื่องและบน Vercel)
functions/     ระบบเดียวกันสำหรับ Cloudflare Pages
test/          ชุดทดสอบ
```
